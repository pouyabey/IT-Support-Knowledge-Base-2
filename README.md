# IT-Support-Knowledge-Base-2


## Golden Troubleshooting Workflow

**Clarify the Issue → Determine the Scope → Check the Basics → Isolate the Cause → Apply the Fix → Verify the Resolution → Document the Issue and Resolution**

### 1. Clarify the Issue
Understand exactly what the user is experiencing and identify the actual symptoms.

Ask questions such as:
- What exactly is happening?
- What should normally happen?
- When did the issue start?
- Are there any error messages?
- Did anything change recently?
- Can the issue be reproduced?

### 2. Determine the Scope
Determine how widespread the issue is and identify who or what is affected.

Check whether the problem affects:
- One user
- One device
- Multiple users
- One department
- One location
- The entire organization

This helps determine whether the issue is related to a specific user, device, application, network, service, or larger infrastructure problem.

### 3. Check the Basics
Start with the simplest and most common possible causes before moving to more complex troubleshooting.

Check things such as:
- Power
- Cables and physical connections
- Network connectivity
- Restarting the device or application
- Correct user account
- Permissions
- Disk space
- Recent updates or configuration changes

### 4. Isolate the Cause
Narrow down the problem by testing different components and eliminating possible causes.

Determine whether the issue is:
- User-specific
- Device-specific
- Application-specific
- Hardware-related
- Network-related
- Account-related
- Service-related

When appropriate, test with known-good users, devices, cables, ports, accounts, or other components.

### 5. Apply the Fix
Apply the least risky solution that addresses the identified cause of the problem.

Whenever possible:
- Change one thing at a time
- Avoid unnecessary changes
- Consider the impact of the change
- Follow existing documentation or procedures
- Avoid making changes that could create additional problems

### 6. Verify the Resolution
Confirm that the original problem has actually been resolved.

Verification may include:
- Repeating the user's original workflow
- Testing the affected application, device, or service
- Confirming with the user that the issue is resolved
- Making sure the fix did not introduce another problem

A troubleshooting task is not complete until the solution has been verified.

### 7. Document the Issue and Resolution
Document what happened, what was tested, and how the issue was resolved.

Include:
- Reported symptoms
- Scope of the issue
- Troubleshooting steps performed
- Relevant errors or logs
- Root cause, if identified
- Resolution
- Verification performed
- Any required follow-up actions
